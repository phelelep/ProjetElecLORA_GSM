### Problematique 
Le code toujours = -2 
ce qui signifique que le module ESP32 ne trouve pas le module LoRa
Tension qui arrive sur module LoRa = **2.9 V** (pas assez ? )

#### Solutions possibles 

1. On va connecter les 2 autres messes du module LoRa à la masse communice pour être sûr 
2. On va founir la tension 3.3 V à partir d'un générateur de tension stable. pour être sûr qu'on a du 3.3V sur le LoRa est le module ESP32.

3. Si ca ne fonctionne pas on va alors ajouter des condensateurs de découplage.

#### Test avec générateur 3.3V 

Après avoir généré la tension de 3.3 avec le générateur on a toujours une erreur de comm entre LoRa et ESP32
```text
--- Test de communication ESP32 <-> LoRa CC68 ---
[LLCC68] Initialisation... ÉCHEC. Code erreur : -2
Erreur: Le module ne répond pas
```

#### Vérification de la tension aux bornes du LoRa

La tension à l'entrée des deux composants LoRa et ESP32 est bien de 3.3 (plus précisément 3.299)

### Vérification du câblage et remplacement de câbles

Après avoir remplacé certains câbles on arrive à recevoir une nouvelle erreur

```text
--- Test de communication ESP32 <-> LoRa CC68 ---
[LLCC68] Initialisation... ÉCHEC. Code erreur : -707

```
L'erreur -707
est spécifique à la bibliothèque RadioLib. Elle correspond à RADIOLIB_ERR_CHIP_NOT_FOUND




### Changement de la carte LoRa CC68-868 GNiceRF -> LoRa GNice

Avec la nouvelle carte on a l'erreur -2 

Code -2 : RADIOLIB_ERR_CHIP_NOT_FOUND
C'est une erreur de connexion totale.

2. Code -707 : RADIOLIB_ERR_INVALID_BUSY_STATE (Spécifique LLCC68/SX126x)
C'est une erreur de dialogue bloqué.


On va revenir à l'ancienne carte alors 



### Utiliser les broches 32 (BUSY) et 33 (DIO1) à la place. Elles possèdent des résistances internes qui stabilisent le signal.
