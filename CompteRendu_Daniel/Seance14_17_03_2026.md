### Étape 2 : Retour au module initial

Le but est de tester `RadioLib.h` et d'enquêter davantage sur l'erreur -707.

Après vérification des pins et modification de certains branchements, on obtient toujours la même erreur -707. Les raisons suspectées sont :
- La patte **BUSY**
- La patte **DIO1**

En effet, en retirant ce branchement, on reçoit toujours l'erreur -707. Ce n'est pas le cas en retirant une autre patte : on reçoit alors l'erreur -2, ce qui indique que le module n'est pas du tout connecté.

#### Observations avec les différentes bibliothèques

**Avec `LoRa.h` et le module RF96 (type SX127x) :**
Le module LLCC68 ne répond pas. La fonction `begin()` ne renvoie aucun code d'erreur, ce qui rend difficile l'investigation ultérieure.

**Avec `RadioLib.h` :**
- Erreur -707 (SPI_CMD_FAILED) quand DIO1 + BUSY sont branchés
- Erreur -2 quand on enlève d'autres pins (NSS/NRST/SPI)

Cela signifie que la communication SPI de base fonctionne (la puce répond), mais une commande spécifique échoue pendant l'initialisation (calibration, configuration des IRQ ou contrôle du TCXO).

Les pattes BUSY et DIO1 sont bien connectées et les pins GPIO utilisés sont compatibles et vérifiés.

#### Autres causes possibles

1. **Alimentation bruitée** : Les puces LLCC68 sont très sensibles aux micro-défaillances de tension pendant les phases critiques de l'initialisation.
2. **Module défectueux**.

#### Pourquoi le premier appel à begin() avec TCXO = 1.6f échoue (-707), alors que le deuxième et le troisième réussissent (0) :
Le premier appel démarre à partir d’un état complètement inconnu ou non initialisé du circuit (après la mise sous tension ou un reset matériel).
Le composant LLCC68 a besoin que la tension du TCXO soit correctement configurée avant que l’oscillateur à quartz puisse se stabiliser et que la calibration puisse s’exécuter.
Lors de la première tentative, la bibliothèque essaie de configurer le TCXO à 1,6 V, mais l’oscillateur interne n’a pas encore démarré ou est dans un mauvais état → la commande de calibration échoue → renvoie -707.
Une fois qu’une première configuration réussit (le deuxième appel renvoie 0), le circuit est correctement initialisé (TCXO activé, oscillateur verrouillé, calibration effectuée).
Les appels suivants partent alors d’un état déjà correct → ils reconfigurent simplement les paramètres sans devoir refaire toute la séquence TCXO/calibration → ils réussissent immédiatement.


### Etape 4 : tester la reception et l'envoi des messages LoRa <-> ESP32

code pour INITIALISER -> envoyer -> ecouter les messages 
```cpp
#include <RadioLib.h>

#define LORA_NSS   5
#define LORA_DIO1  36
#define LORA_NRST  27
#define LORA_BUSY  33

LLCC68 radio = new Module(LORA_NSS, LORA_DIO1, LORA_NRST, LORA_BUSY);


unsigned long lastTx = 0;
const unsigned long TX_INTERVAL = 5000;  // send every 5 seconds


void setup() {
  Serial.begin(115200);
  delay(2000);

  pinMode(LORA_NRST, OUTPUT);
  pinMode(LORA_DIO1, INPUT);
  pinMode(LORA_BUSY, INPUT);

  Serial.println("\n=== Multiple LLCC68 begin() tests  ===\n");

  // Reset once at beginning
  digitalWrite(LORA_NRST, LOW);
  delay(50);
  digitalWrite(LORA_NRST, HIGH);
  delay(500);
  Serial.print("BUSY after initial reset: "); Serial.println(digitalRead(LORA_BUSY));

  int state= -1; 
  // tester jussq'au succes
  while (state != RADIOLIB_ERR_NONE)
  {
    state = radio.begin(868.0, 125.0, 9, 7, 0x12, 10, 8, 1.6f);
    Serial.print("begin() = "); Serial.println(state);
    if (state == RADIOLIB_ERR_NONE) 
      Serial.print("Initialization SUCCESS! - code : "); Serial.println(state);
    else 
       Serial.print("Init FAILED - code "); Serial.println(state);
    delay(1500);
  }

  // Start continuous receive mode
  radio.startReceive();
  Serial.println("Listening for packets...");
}

void loop() {
  // Send periodically
  if (millis() - lastTx >= TX_INTERVAL) {
    lastTx = millis();

    String message = "Hello from ESP32 at " + String(millis() / 1000) + "s";

    Serial.print("Sending: "); Serial.println(message);

    int state = radio.transmit(message);

    if (state == RADIOLIB_ERR_NONE) {
      Serial.println("→ Sent OK");
    } else {
      Serial.print("→ Send failed, code "); Serial.println(state);
    }
  }

  // Check for incoming packet
  String received = "";
  int state = radio.receive(received);

  if (state == RADIOLIB_ERR_NONE) {
    // Packet received!
    Serial.println("Received packet:");
    Serial.print("  Message: "); Serial.println(received);
    Serial.print("  RSSI: "); Serial.print(radio.getRSSI()); Serial.println(" dBm");
    Serial.print("  SNR: "); Serial.print(radio.getSNR()); Serial.println(" dB");
    Serial.println();
  } else if (state != RADIOLIB_ERR_RX_TIMEOUT) {
    // Some error (not just timeout)
    Serial.print("Receive error, code "); Serial.println(state);
  }

  // Small delay to avoid CPU hogging
  delay(10);
}
```

#### Description du processus de communication entre les deux ESP32
- Les deux ESP32 ne sont pas reliés par fil (pas d'I2C, UART, USB, etc.).
Ils communiquent uniquement par ondes radio LoRa via leurs antennes.

- Chaque ESP32 + module LoRa a une petite antenne 868 MHz .
Quand un côté envoie, l'énergie RF sort par l’antenne → se propage dans l’air (jusqu’à plusieurs centaines de mètres en extérieur, 50–200 m en intérieur selon puissance et environnement).
L’autre côté reçoit ce signal grâce à son antenne → le module LoRa le décode → le passe à l’ESP32.

et c'est en foncitonn de la frequence qu'on a arrive à se synchroniser sur le deux EPS32 en même temps 

L’antenne capte le signal RF (ondes électromagnétiques à 868 MHz).
